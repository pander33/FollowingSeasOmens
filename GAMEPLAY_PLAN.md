# План игровых механик Following Seas Omens

Дата: 2026-10-16, обновлён 2026-10-17. Статус: реализовано в рабочей копии master (без коммита), собрано;
игровые проверки ещё не пройдены. Текущее состояние кода: `session-state/GAMEPLAY_HANDOFF.md`.
Документ сохраняет проектные решения и критерии приёмки; наличие раздела не означает успешную проверку механики.

## 1. Зафиксированные решения

| Явление | Игровое действие | Чего не делаем |
|---|---|---|
| Кровавая луна | Более частый клёв и более крупная рыба | Никаких дополнительных штрафов, включая усиление сопротивления из-за бонусного размера |
| Северное сияние | Дрожание магнитного компаса | Не поворачиваем корабль, камеру или мировой север |
| Светящееся море | Светящиеся рыбные места с настоящей пользой для ловли; читаемые пена и прибой | Не рисуем ложные рыбные места и не раскрываем подводный рельеф |
| Тёмная ночь | Уже существующее ограничение видимости на всю ночь | Не добавляем урон, замедление или ускоренный расход фонарей |

Длительность всех естественных явлений привязана к ночи Enviro, не к отдельному таймеру.
Около 04:00–12:00 игровых часов для ранее проверенного местоположения, но не жёстко заданный интервал.
Настройка FadeSeconds задаёт переход, а не продолжительность ночи.

Предлагаемые ниже числа являются начальными значениями для игровой настройки, а не уже согласованным балансом.
Дизайн рыбных мест как собственных зон мода принят поручением реализовать этот план:
в просмотренных игровых системах не обнаружена модель естественных косяков, которую можно просто подсветить.

## 2. Что подтверждено текущими исходниками

### Мод

Раздел описывает мод до начала игровых механик (0.1.0).


- Omen.cs: Tick меняет Level; Apply вызывает Draw с силой Level × darkness. Active может быть true при нулевой фактической силе.
- OmenDirector.cs: выбирает события ночью, выключает их днём, блокирует несовместимые события и передаёт состояние гостям.
- DarkNight несовместима с тремя светлыми явлениями; остальные могут совпадать.
- GlowingSea.cs меняет четыре цвета материала Crest. Это глобальное свечение пены/воды, не пространственные рыбные места.

- Plugin.cs содержит настройки вероятностей и внешнего вида, но не игровые модификаторы.
- FollowingSeasOmens.csproj: netstandard2.1, C# 9; Harmony берётся из BepInEx/core (`Private=false`).

## 3. Общая интеграция

### Сила эффекта

OmenDirector должен публиковать для игровых механизмов вычисленную фактическую силу каждого явления
после применения блокировок и выполнения Apply. Не использовать один Wanted, Active или Level.
При ошибке визуального события, несовместимости или отсутствии мира сила соответствующего механизма равна нулю.

Для коэффициента M использовать multiplier(s) = 1 + (M - 1) × s, где s находится в [0, 1].
Для углов и прозрачности умножать амплитуду на s. При s = 0 игровое поведение полностью штатное.
Ручной F9 пользуется теми же механизмами; дневной вызов не даёт бонусов до темноты.

### Настройки

Предлагается Gameplay.Enabled = true и отдельные переключатели трёх новых механик.
При Gameplay.Enabled = false остаются нынешние визуальные эффекты, включая темноту DarkNight.
Это не обещание вернуть видимость в тёмную ночь: затемнение и есть её существующий эффект.

| Раздел / ключ | Начальное значение | Назначение |
|---|---|---|
| Gameplay / Enabled | true | Включить новые игровые механики |
| BloodMoon / FishingEnabled | true | Бонусы обеих систем рыбалки |
| BloodMoon / BiteMultiplier | 1.5 | Частота клёва |
| BloodMoon / SizeBiasMultiplier | 0.65 | Снижение показателя распределения размера, диапазон (0, 1] |
| Aurora / CompassEnabled | true | Дрожание магнитных приборов |
| Aurora / CompassAmplitudeDegrees | 8 | Максимальный модуль отклонения |
| GlowingSea / FishingPatchesEnabled | true | Светящиеся рыбные места |
| GlowingSea / PatchBiteMultiplier | 1.5 | Локальный бонус клёва внутри пятна |

Частоты колебаний и плотность пятен сначала оставить константами, не перегружать конфигурацию.
Для чисел задать допустимые диапазоны BepInEx. Настройки игрового мира определяет хост.

### Точки расширения и зависимости

Новые игровые перехваты держать отдельно от визуальных BloodMoon.cs и Aurora.cs:
FishingEffects.cs для двух видов рыбалки, CompassEffects.cs для подтверждённых магнитных приборов,
FishingPatches.cs для зон и их визуализации. Каждая группа перехватов ставится и снимается отдельно.
Общий текущий контекст хранить у директора, не строить универсальную систему статусов.

Для закрытых игровых методов предполагаются адресные Harmony-патчи. Сначала проверить имеющуюся
BepInEx/core/0Harmony.dll и совместимость с модом co-op. Не добавлять NuGet без отдельного согласования.
Использовать отдельный Harmony ID мода, снимать только собственные патчи.
Ни декомпилированные реализации целиком, ни игровые DLL не включать в пакеты.

## 4. Кровавая луна

### Более частый клёв

Удочка: менять только длительность первого ожидания в Bite, а не глобальный Random.Range или все WaitForSeconds.
Предпочтительный перехват: адресный transpiler MoveNext итератора Bite, заменяющий вычисленное время ожидания
вызовом небольшого помощника. Найденный IL-паттерн должен быть однозначным; при несовпадении отключить
только эту интеграцию с одним понятным предупреждением, не применять частичный патч.
Не заменять всю корутину: сохранить создание рыбы, проверку крючка, вибрацию и штатные побочные действия.

wait = vanillaWait / multiplier(s). При полной силе 1.5 это примерно 3.3–12.7 с вместо диапазона 5–19 с.
Сила и положение крючка фиксируются в начале ожидания. Уже начавшееся ожидание не пересоздавать на рассвете.
Так не возникают двойные поклёвки и вмешательство в штатную отмену корутины.

Троллинг: оставить период проверки прежним, поднять шанс подходящей свободной подводной точки
с 0.25 до min(1, 0.25 × multiplier(s)). На полной силе получается 0.375.
Перехватить только проверку шанса нужной перегрузки RollForFish, не дублировать выдачу рыбы в Postfix.
Проверить и вторую перегрузку с GameObject: включать её в интеграцию, если найдены реальные вызовы.

### Более крупная рыба без повышенной сложности

Для удочки сохранить исходную случайную выборку u. Обычный нормированный размер t = u^bias;
бонусный t' = u^(bias × lerp(1, 0.65, s)). При том же u размер не уменьшается и остаётся в диапазоне вида.
Вес, длина и масштаб вычисляются согласованно из t'. Сложность оставить вычисленной из исходного t.
Не менять вид, редкость, скорость вываживания, таймеры срыва и сопротивление.

Патч Fish.Awake ограничить контекстом FishingController.GetFish конкретного экземпляра.
Контекст снять в Harmony Finalizer даже при исключении; поддержать вложенность, не оставлять глобальный bool.
Сохранить исходное число обращений к Unity Random: не делать повторный розыгрыш ради бонуса.
Результат закрепить при создании добычи: пойманная ночью рыба не уменьшается на рассвете.

Троллинг: аналогично снизить показатель исходного распределения масштаба с 2 до lerp(2, 1.3, s).
Решение пользователя при реализации: бонусный размер троллинговой рыбы даёт дополнительные
штатные товарные единицы. За каждую пересечённую бонусом четверть нормированного диапазона
размера начисляется одна дополнительная единица при сдаче рыбы в трюм; награда фиксируется при улове.
Не выходить за minScale/maxScale. До реализации обязательно проверить, как масштаб связан с весом,
товаром и сохранением: визуально крупная рыба без реального выигрыша не закрывает это направление.
Если конечный вес генерируется отдельно, перенести бонус в авторитетное создание улова и согласовать визуал.

## 5. Северное сияние

### Дрожание, а не постоянная ошибка курса

Базовая функция: offset = amplitude × s × (0.65 × sin(2π × 0.7 × t + phase)
+ 0.35 × sin(2π × 1.9 × t + phase2)). Модуль не больше amplitude, среднего постоянного сдвига нет.
Фазы получаются из Omen.Seed без изменения Unity Random.state. При паузе локального мира дрожание замирает.
Не добавлять пока редкие развороты стрелки, полный отказ компаса и отдельный штраф за шторм.

### Применение без накопления поворота

В игре сначала инвентаризировать ручной и судовой магнитные компасы: путь объекта, компонент, ось,
связь UI и физической стрелки. Не затрагивать немагнитные угломерные приборы, даже если у них общий компонент.

Снимать только собственный прошлый поворот перед следующим обновлением штатного прибора;
после штатного обновления добавлять свежий offset к полученному базовому направлению.
Нельзя каждый LateUpdate умножать уже искажённый transform и затем сохранять это как новую базу:
сглаживание игры создаст дрейф. При выключении и уничтожении компонента снять собственную поправку.

Текст азимута и сохраняемое показание магнитного прибора должны включать ту же поправку,
иначе цифры станут обходом механики. Для HandheldCompassManager момент коррекции текста должен
предшествовать сохранению savedAzimuth внутри Update, а не просто выполняться в Postfix после него.
Выбрать адресный перехват вычисления азимута после проверки IL; не менять camera.rotation.
UICompass либо наследует отклонение от подтверждённого источника, либо получает его один раз, не дважды.

## 6. Светящееся море

### Честные рыбные места

В просмотренной реализации клёв не зависит от существующей карты рыбных косяков.
Поэтому предлагается явная новая механика: зоны ночной кормёжки мода, где одновременно есть
светящийся поверхностный рисунок и настоящий бонус клёва. Это не заявление о найденных игровых стаях.
Вне пятен рыбалка остаётся обычной; внутри не гарантирован улов, но шанс/частота реально выше.
Отдельного бонуса размера пятна не дают, чтобы сохранить роль кровавой луны.

### Генерация и жизненный цикл

- Стартовые параметры: сетка мировых ячеек 500 м, вероятность пятна в ячейке 0.2, радиус пятна 40 м.
- До одного пятна на ячейку; seed = детерминированный hash(ночь, Omen.Seed, координаты ячейки).
- Зоны стабильны всю ночь; не пересоздаются вслед за игроком и не меняются после загрузки.
- Использовать устойчивые координаты мира, учитывающие origin shifting. Конкретный перевод из worldRoot
  в такие координаты сначала подтвердить в игре, не считать transform.position абсолютным.
- Принять зону только после проверки воды и отсутствия суши с фактическими слоями сцены
  (лучи до уровня моря; корабли и груз с Rigidbody сушей не считаются).
  Нельзя выбирать случайные пятна на суше, а затем давать там бонус.
- Рассчитывать зону одинаковой функцией для визуала и клёва; проверять крючок удочки или конкретный FishPoint,
  а не центр игрока/корабля. На границе использовать плавный falloff по расстоянию.
- Отрисовывать только ближайшие принятые зоны, максимум 8; ограничение рендера не меняет мировую модель.
  Дальность появления подбирать так, чтобы ближайшее пригодное для ловли пятно не было невидимым.

### Видимость и вода

Сохранить уже одобренное общее свечение GlowingSea, пены и прибоя. Поверх добавить редкие
голубые кольца/короткие всплески в рыбных зонах, без стрелок, надписей, маркеров карты и подсветки дна.
Пул небольших mesh/particle объектов, один общий материал; высота по поверхности Crest
(у каждого кольца свой запрос высоты: ответ Crest приходит позже и только для заданной точки),
обновление пространственного окружения примерно раз в секунду, а анимация локально каждый кадр.
Шейдер проверить на Low и остальных качествах: прежние эксперименты показали, что часть URP-материалов
теряется за туманом. Не считать работоспособность Sprites/Default достаточной проверкой нового эффекта.

Вход в пятно влияет только на новую проверку клёва/новое ожидание, не создаёт вторую рыбу на занятом крючке.
При совпадении с кровавой луной множители клёва перемножаются с общим пределом 2.0.
При предложенных значениях полное совпадение даёт 2.0, а не 2.25; размер меняет только луна.

## 7. Тёмная ночь

Сохранить нынешнюю механику на всю выпавшую ночь. Не вводить отдельную длительность или дополнительные штрафы.
Фонарь остаётся рабочим, базовая подсветка игрока затемняется. Конфликт с другими тремя явлениями сохраняется.

Обязательная игровая проверка перед следующим релизом: последние правки ambientIntensity и градиентов
объёмных облаков ещё не подтверждены в игре. Проверить дневной F9 при силе 0, плавный выход на рассвете,
восстановление света игрока, смену мира и качества. При силе 0 не должно быть изменений видимости.
Не обещать абсолютную чёрноту на всех настройках до такой проверки.

## 8. Co-op, сохранения и совместимость

### Авторитет

Сначала проследить существующий co-op путь обеих систем рыбалки: где выбирается добыча, кто считает
Food/товар и кто сохраняет. Это обязательная зависимость до написания патчей выдачи награды.
Не предполагать, что вся рыбалка уже исполняется на хосте. Каждое событие улова обрабатывать ровно
один раз в его текущем авторитетном месте; не дублировать рыбу или провизию на госте.

Хост задаёт события, игровые переключатели, коэффициенты, seed и номер ночи.
Гость использует принятые настройки, а не собственный конфиг. Дрожание локально, без передачи углов
каждый кадр; достаточно seed, силы и временной опоры хоста. Часы гостя не должны определять другую ночь.

### Сообщения

Не ломать существующее сообщение визуальных событий версии 1. Для новой игровой схемы использовать
отдельный канал com.followingseas.omens.gameplay с версией 1, handshake возможностей и снимком состояния.
Снимок включает номер ночи, seed зон, включённые механики, числовые настройки и временную опору.
Для принятых водных зон хост передаёт ID и устойчивые координаты/радиус; это исключит разный набор
зон у клиентов с различным загруженным окружением. Поздно подключившийся гость получает полный снимок.

Проверять версию, длину, диапазоны и конечность чисел входящих данных. Использовать InvariantCulture.
Снимок обновлять при изменениях и периодически; изменения зон передавать пакетами, не на кадр.
Если ModChannel не предоставляет хосту события подключения, предусмотреть запрос снимка гостем
и подтверждение версии через тот же канал, после проверки реального API транспорта.

Без подтверждённой совместимости участников новые игровые механики в co-op выключены,
а поддерживаемые старым протоколом визуалы продолжают работать. Включать игровые бонусы на хосте
только после определения полного состава участников; если текущий API не даёт его узнать,
потребуется небольшое расширение co-op API до выпуска мультиплеерной части.
Не полагаться на отсутствие ответа как доказательство отсутствия старого клиента.

### Сохранения

Не менять формат игровых файлов. Ночь и зоны восстанавливать детерминированно; исходный seed ночи
уже является частью состояния явлений. Проверить совпадение после save/load на той же ночи.
Вес уже пойманной рыбы и рекорды являются законным постоянным результатом, их не откатывать.
Временные модификаторы и объекты не записывать как постоянные изменения префабов/сцены.

## 9. Последовательность реализации

1. Проверить актуальные игровые IL-сигнатуры, сцены компасов, перевод координат и оба пути наград рыбалки.
   Отдельно подтвердить co-op авторитет и доступность списка участников. Результат: точные точки перехвата.
2. Добавить конфиг и единый контекст фактической силы; доказать отсутствие действий при s = 0.
3. Реализовать бонус кровавой луны для удочки и троллинга, включая размер и неизменную сложность.
4. Реализовать магнитное дрожание с согласованными цифрами/сохраняемым азимутом и без накопления.
5. Реализовать стабильную модель рыбных зон, затем её визуал и локальный бонус клёва.
6. Добавить согласование игровых настроек/зон и авторитетную выдачу улова в co-op.
7. Проверить DarkNight в игре, совместные явления, очистку объектов и возврат состояния.
8. После реального прогона обновить README, описания конфигурации и release notes: фраза
   «omens only change how the night looks» для нового режима перестанет быть верной.
   Номер следующего релиза выбрать отдельно; этот план не меняет опубликованный v0.1.0.

Этапы являются зависимостями разработки, а не предложением выпустить неполную реализацию.
Не публиковать новую игровую версию, пока одно из согласованных направлений остаётся декоративной заглушкой.

## 10. Проверка и критерии готовности

Тестовых проектов сейчас нет. Не создавать отдельную тестовую инфраструктуру только ради плана.
При реализации использовать Release-сборку, Rider inspections и временные диагностические измерения
через DevConsole; окончательная проверка только в игре. До запуска сделать резервную копию сохранений:
тестовая копия игры автоматически сохраняется.

| Сценарий | Что должно наблюдаться |
|---|---|
| Gameplay.Enabled = false | Нынешний визуальный мод, штатная рыбалка и компас |
| Дневной F9 / сила 0 | Нет бонусов, дрожания, рыбных всплесков и побочного затемнения |
| Кровавая луна, удочка | Серия измерений показывает меньшее ожидание; вес, длина, UI и Food согласованы |
| Одинаковые u при разной силе | Бонусный размер не меньше обычного, не выше максимума вида; difficulty неизменна |
| Кровавая луна, троллинг | Выше доля успешных подходящих проверок; реальные размер/награда увеличены |
| Нет воды / занятый крючок / убранные снасти | Бонус не обходит игровые условия и не создаёт дубликат |
| Северное сияние | Подтверждённые магнитные приборы дрожат в заданных пределах; цифры и запись соответствуют стрелке |
| Длительное сияние, повороты корабля | Нет накапливающегося смещения, дрожания камеры и немагнитных приборов |
| Светящееся пятно | Видимый рисунок и повышенный клёв совпадают по месту и силе; снаружи обычный клёв |
| Луна + сияние + море | Все эффекты работают, предел общего клёва 2.0 соблюдён |
| DarkNight | Остальные эффекты отсутствуют; фонари работают; после рассвета освещение восстановлено |
| Пауза, смена мира, выход, исключение | Нет утечки патч-контекста, поправок компаса, объектов и материалов |
| Save/load в ту же ночь | Тот же набор событий/зон, сохранённая добыча не пересчитывается |
| Host + guest + late join | Одинаковые зоны и правила, одна выдача награды, локальный конфиг гостя не меняет бонус |
| Старый/неполный набор модов | Новые механики co-op отключены с ясным объяснением, нет скрытого рассогласования |
| Low и более высокое качество | Пятна видны корректно, облака и восстановление DarkNight проверены |
| 20 минут плавания с зонами | Нет растущего числа объектов/материалов, покадровых поисков всей сцены и заметного GC от новой логики |

Для статистики клёва сравнивать сотни проверок троллинга и распределение ожиданий удочки,
а не вывод по двум поклёвкам. Для отсутствия штрафа сравнивать одинаковую исходную случайную выборку.
Проверить паузу, ускорение/перевод времени и границы ночи отдельно от обычного течения времени.
Никакой пункт этой таблицы данным документом не объявляется уже пройденным.
